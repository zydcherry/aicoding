### 1.2 架构特点

#### 1.2.1 三种接入模式设计

**方式1：同步推送（POST /notifications/sync）**
- **特点**：立即执行推送，同步返回推送结果
- **返回**：notificationId + 推送结果详情
- **适用**：强一致性要求、需要立即知道推送结果的场景（如支付通知）
- **优先级**：支持HIGH/NORMAL，高优先级立即执行
- **性能**：受订阅者响应时间影响，适合少量关键通知

**方式2：异步API（POST /notifications/async）**
- **特点**：创建通知记录后立即返回，异步推送（通过Kafka）
- **返回**：notificationId（可用于追踪和对账）
- **适用**：高吞吐量、允许异步处理的场景（如订单通知）
- **优先级**：支持HIGH/NORMAL，写入不同Kafka分区
- **性能**：毫秒级响应，不受推送影响

**方式3：Kafka直连**
- **特点**：业务系统直接发送到Kafka，完全解耦
- **返回**：无返回值（消息写入Kafka即成功）
- **适用**：大规模、超高吞吐量场景（如日志采集）
- **优先级**：通过消息中的priority字段指定，发送到对应分区
- **性能**：最高吞吐量，支持10000+ QPS

#### 1.2.2 优先级队列设计
- **Kafka分区策略**：
  - 高优先级：partition 0-3（4个分区，3个专属Consumer）
  - 普通优先级：partition 4-11（8个分区，6个Consumer）
- **Consumer配置**：高优先级Consumer优先消费，资源保障
- **场景示例**：
  - HIGH：支付成功通知、账户异常告警、实时交易通知
  - NORMAL：订单创建、用户注册、日常业务通知

#### 1.2.3 追踪与对账机制
- **notificationId生成规则**：`noti_` + timestamp(10位) + random(6位)
- **追踪查询**：通过notificationId查询推送状态、重试记录、响应详情
- **对账能力**：
  - 业务系统保存notificationId到业务表
  - 定期对账：查询通知状态，确认是否成功推送
  - 失败补偿：根据notificationId触发重推

#### 1.2.4 统一处理保证
- **方式1**：直接调用推送服务，不经过Kafka
- **方式2、3**：都写入Kafka，共享消费逻辑
- **幂等性**：基于eventId + notificationId双重去重
- **数据一致性**：所有方式的通知记录都持久化到MySQL

#### 1.2.5 分层架构
- **接入层**：同步推送 + 异步API + Kafka直连
- **应用层**：业务逻辑处理（订阅管理、通知创建）
- **消息层**：Kafka优先级队列（高优先级/普通优先级）
- **推送层**：异步HTTP推送和重试调度
- **适配层**：多供应商API格式适配
- **存储层**：数据持久化

#### 1.2.6 适配器模式设计（核心）
- **供应商解耦**：支持不同业务系统的API格式差异（第三方CRM、ERP、物流系统等）
- **灵活适配**：通过标准格式和自定义模板适配任意HTTP API
- **格式转换**：自动处理Body/Header/认证方式的差异
- **边界清晰**：专注于B2B系统集成，不包含IM平台（钉钉、企微等）

#### 1.2.7 高可用设计
- **无状态服务**：应用层无状态，支持水平扩展
- **消息持久化**：Kafka保证消息持久化，防止丢失
- **失败重试**：自动重试机制
- **监控告警**：实时监控系统状态

### 2.3 消息队列

#### 2.3.1 Kafka集群配置（支持优先级）

**用途**：
- 接收业务系统发布的事件/通知
- 实现业务系统与通知系统的解耦
- 通过分区实现优先级队列
- 保证消息的可靠传递和顺序性

**Kafka配置**：
```yaml
spring:
  kafka:
    bootstrap-servers: localhost:9092
    consumer:
      group-id: notification-system-consumer-group
      enable-auto-commit: false
      auto-offset-reset: earliest
      max-poll-records: 100
      fetch-min-size: 1024
      fetch-max-wait-ms: 500
    producer:
      acks: all
      retries: 3
      
# Topic配置
kafka:
  topic:
    notification-events: notification-events
  # 优先级Consumer配置
  consumer:
    high-priority:
      concurrency: 3      # 高优先级Consumer数量
      partitions: 0-3     # 监听分区0-3
    normal-priority:
      concurrency: 6      # 普通优先级Consumer数量
      partitions: 4-11    # 监听分区4-11
```

**Topic设计（优先级分区）**：
- **Topic名称**：`notification-events`
- **总分区数**：12个
  - **高优先级分区**：0-3（4个分区）
  - **普通优先级分区**：4-11（8个分区）
- **副本因子**：3（生产环境）
- **消息保留**：7天

**分区路由策略**：
```java
/**
 * 根据优先级选择分区
 */
public int selectPartition(String priority) {
    if ("HIGH".equals(priority)) {
        // 高优先级：随机选择 0-3 分区
        return ThreadLocalRandom.current().nextInt(4);
    } else {
        // 普通优先级：随机选择 4-11 分区
        return ThreadLocalRandom.current().nextInt(8) + 4;
    }
}
```

#### 2.3.2 消息可靠性保证
**生产者端（业务系统/通知系统）**：
- `acks=all`：等待所有副本确认
- `retries=3`：失败自动重试
- `enable.idempotence=true`：启用幂等性

**消费者端（通知系统）**：
- 手动提交offset（`enable-auto-commit=false`）
- 批量处理完成后统一提交
- 处理失败的消息记录到失败表

**优先级保证**：
- 高优先级Consumer独占分区0-3
- 普通优先级Consumer独占分区4-11
- 两组Consumer独立消费，互不影响
- 高优先级消息优先得到处理

**选型理由**：
- Kafka是企业级消息队列，性能和可靠性都有保证
- 支持高吞吐量和分区并行消费
- 通过分区天然实现优先级队列
- 消息持久化，不会丢失
- 适合事件驱动架构

**用途**：向订阅者推送HTTP通知

**特点**：
- 非阻塞异步调用


### 3.2 索引设计

#### 3.2.1 索引策略
- **主键索引**：所有表使用自增主键
- **唯一索引**：业务唯一ID（subscription_id, event_id等）
- **普通索引**：高频查询字段（status, created_at等）
- **复合索引**：多条件查询场景

#### 3.2.2 查询优化
- 订阅查询：通过subscription_id或subscriber_name
- 事件查询：通过event_id或business_id
- 通知查询：通过event_id或subscription_id
- 重试任务：通过next_retry_time + status

### 3.3 数据归档策略

#### 3.3.1 归档规则
- **事件数据**：保留30天，超过后归档到历史表
- **通知数据**：保留30天，超过后归档到历史表
- **订阅数据**：长期保留

```java
@Service
@Slf4j
public class SubscriptionService {
    
    @Autowired
    private SubscriptionRepository subscriptionRepository;
    
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
    
    /**
     * 创建订阅
     */
    public SubscriptionResponse createSubscription(CreateSubscriptionRequest request) {
        // 1. 参数验证
        validateSubscription(request);
        
        // 2. 检查是否重复订阅
        checkDuplicateSubscription(request.getSubscriberName(), request.getEventTypes());
        
        // 3. 创建订阅记录
        Subscription subscription = new Subscription();
        subscription.setSubscriberName(request.getSubscriberName());
        subscription.setCallbackUrl(request.getCallbackUrl());
        subscription.setEventTypeList(request.getEventTypes());
        subscription.setSecretKey(request.getSecretKey());
        subscription.setDescription(request.getDescription());
        subscription.setStatus(SubscriptionStatus.ACTIVE);
        
        Subscription saved = subscriptionRepository.save(subscription);
        
        // 4. 清除缓存
        clearSubscriptionCache();
        
        log.info("创建订阅成功: subscriptionId={}, subscriberName={}", 
                saved.getSubscriptionId(), saved.getSubscriberName());
        
        return convertToResponse(saved);
    }
    
    /**
     * 查询订阅
     */
    public List<SubscriptionResponse> querySubscriptions(QuerySubscriptionRequest request) {
        // 从数据库查询
        List<Subscription> subscriptions = subscriptionRepository.findByConditions(
            request.getSubscriberName(),
            request.getEventType(),
            request.getStatus()
        );
        
        return subscriptions.stream()
            .map(this::convertToResponse)
            .collect(Collectors.toList());
    }
    
    /**
     * 根据事件类型查找订阅
     */
    public List<Subscription> findSubscriptionsByEventType(String eventType) {
        // 先从缓存获取
        String cacheKey = "subscriptions:eventType:" + eventType;
        List<Subscription> cached = (List<Subscription>) redisTemplate.opsForValue().get(cacheKey);
        if (cached != null) {
            return cached;
        }
        
        // 缓存未命中，从数据库查询
        List<Subscription> subscriptions = subscriptionRepository.findByEventTypeAndStatus(
            eventType, SubscriptionStatus.ACTIVE
        );
        
        // 写入缓存，5分钟过期
        redisTemplate.opsForValue().set(cacheKey, subscriptions, 5, TimeUnit.MINUTES);
        
        return subscriptions;
    }
    
    /**
     * 更新订阅
     */
    public SubscriptionResponse updateSubscription(String subscriptionId, UpdateSubscriptionRequest request) {
        Subscription subscription = subscriptionRepository.findBySubscriptionId(subscriptionId)
            .orElseThrow(() -> new BusinessException(ErrorCode.SUBSCRIPTION_NOT_FOUND));
        
        // 更新字段
        if (request.getCallbackUrl() != null) {
            subscription.setCallbackUrl(request.getCallbackUrl());
        }
        if (request.getEventTypes() != null) {
            subscription.setEventTypeList(request.getEventTypes());
        }
        if (request.getStatus() != null) {
            subscription.setStatus(request.getStatus());
        }
        
        Subscription updated = subscriptionRepository.save(subscription);
        
        // 清除缓存
        clearSubscriptionCache();
        
        return convertToResponse(updated);
    }
    
    /**
     * 删除订阅（软删除）
     */
    public void deleteSubscription(String subscriptionId) {
        Subscription subscription = subscriptionRepository.findBySubscriptionId(subscriptionId)
            .orElseThrow(() -> new BusinessException(ErrorCode.SUBSCRIPTION_NOT_FOUND));
        
        subscription.setStatus(SubscriptionStatus.DELETED);
        subscriptionRepository.save(subscription);
        
        // 清除缓存
        clearSubscriptionCache();
        
        log.info("删除订阅成功: subscriptionId={}", subscriptionId);
    }
    
    private void validateSubscription(CreateSubscriptionRequest request) {
        // URL格式验证
        if (!isValidUrl(request.getCallbackUrl())) {
            throw new BusinessException(ErrorCode.INVALID_CALLBACK_URL);
        }
        
        // 事件类型验证
        for (String eventType : request.getEventTypes()) {
            if (!EventTypeEnum.isValid(eventType)) {
                throw new BusinessException(ErrorCode.INVALID_EVENT_TYPE, eventType);
            }
        }
    }
    
    private void checkDuplicateSubscription(String subscriberName, List<String> eventTypes) {
        // 检查是否已订阅相同的事件类型
        List<Subscription> existing = subscriptionRepository.findBySubscriberNameAndStatus(
            subscriberName, SubscriptionStatus.ACTIVE
        );
        
        for (Subscription sub : existing) {
            List<String> existingTypes = sub.getEventTypeList();
            for (String type : eventTypes) {
                if (existingTypes.contains(type)) {
                    throw new BusinessException(ErrorCode.DUPLICATE_SUBSCRIPTION, type);
                }
            }
        }
    }
    
    private void clearSubscriptionCache() {
        Set<String> keys = redisTemplate.keys("subscriptions:*");
        if (keys != null && !keys.isEmpty()) {
            redisTemplate.delete(keys);
        }
    }
    
    private SubscriptionResponse convertToResponse(Subscription subscription) {
        SubscriptionResponse response = new SubscriptionResponse();
        BeanUtils.copyProperties(subscription, response);
        response.setEventTypes(subscription.getEventTypeList());
        return response;
    }
}
```

### 4.3 通知接入模块（三种方式）

#### 4.3.0 三种接入模式说明

系统提供三种通知接入方式，满足不同业务场景：

**方式1：同步推送（SYNC）**
- 接口：`POST /api/v1/notifications/sync`
- 特点：立即执行推送，同步返回结果
- 返回：notificationId + 推送状态 + 响应详情
- 适用：支付通知、告警通知等强一致性场景
- 性能：受订阅者响应时间影响（通常1-3秒）

**方式2：异步API（ASYNC）**
- 接口：`POST /api/v1/notifications/async`
- 特点：创建通知后立即返回，异步推送
- 返回：notificationId（用于追踪）
- 适用：订单通知、用户注册等高吞吐场景
- 性能：毫秒级响应（< 50ms）

**方式3：Kafka直连（KAFKA）**
- 接口：直接发送到Kafka Topic
- 特点：完全解耦，最高性能
- 返回：无（Kafka确认即可）
- 适用：日志采集、数据同步等超大规模场景
- 性能：最高吞吐量（> 10000 QPS）

```java
@Service
@Slf4j
public class NotificationSyncService {
    
    @Autowired
    private SubscriptionService subscriptionService;
    
    @Autowired
    private NotificationRepository notificationRepository;
    
    @Autowired
    private NotificationPushService notificationPushService;
    
    /**
     * 同步推送
     */
    @Transactional
    public SyncPushResponse syncPush(SyncPushRequest request) {
        // 1. 查找订阅者
        List<Subscription> subscriptions = subscriptionService
                .findActiveSubscriptionsByEventType(request.getEventType());
        
        if (subscriptions.isEmpty()) {
            throw new BusinessException(ErrorCode.NO_SUBSCRIBER, "没有订阅者");
        }
        
        // 2. 创建事件记录
        Event event = createEvent(request);
        
        // 3. 为每个订阅者创建通知并立即推送
        List<PushResult> results = new ArrayList<>();
        int successCount = 0;
        int failedCount = 0;
        String notificationId = null;
        
        for (Subscription subscription : subscriptions) {
            // 创建通知记录
            Notification notification = createNotification(event, subscription, request.getPriority());
            if (notificationId == null) {
                notificationId = notification.getNotificationId();  // 返回第一个通知ID
            }
            
            // 立即推送
            PushResult result = notificationPushService.pushImmediately(notification, event, subscription);
            results.add(result);
            
            if ("SUCCESS".equals(result.getStatus())) {
                successCount++;
            } else {
                failedCount++;
            }
        }
        
        return SyncPushResponse.builder()
                .notificationId(notificationId)
                .status(failedCount == 0 ? "SUCCESS" : "PARTIAL")
                .successCount(successCount)
                .failedCount(failedCount)
                .results(results)
                .build();
    }
    
    private Notification createNotification(Event event, Subscription subscription, String priority) {
        Notification notification = new Notification();
        notification.setNotificationId(IdGenerator.generateNotificationId());
        notification.setEventId(event.getEventId());
        notification.setSubscriptionId(subscription.getSubscriptionId());
        notification.setSubscriberName(subscription.getSubscriberName());
        notification.setCallbackUrl(subscription.getCallbackUrl());
        notification.setPriority(priority);
        notification.setAccessMode("SYNC");
        notification.setStatus(NotificationStatus.PENDING);
        
        return notificationRepository.save(notification);
    }
}
```

```java
@Service
@Slf4j
public class NotificationAsyncService {
    
    @Autowired
    private KafkaTemplate<String, String> kafkaTemplate;
    
    @Autowired
    private NotificationRepository notificationRepository;
    
    @Value("${kafka.topic.notification-events}")
    private String eventTopic;
    
    /**
     * 异步推送 - 发送到Kafka
     */
    @Transactional
    public AsyncPushResponse asyncPush(AsyncPushRequest request) {
        // 1. 生成ID
        String eventId = IdGenerator.generateEventId();
        String notificationId = IdGenerator.generateNotificationId();
        
        // 2. 创建事件记录
        Event event = createEvent(request, eventId);
        
        // 3. 创建通知记录（状态为PENDING）
        createNotificationRecords(event, request.getPriority(), notificationId);
        
        // 4. 构建Kafka消息
        NotificationMessage message = NotificationMessage.builder()
                .notificationId(notificationId)
                .eventId(eventId)
                .eventType(request.getEventType())
                .eventData(request.getEventData())
                .businessId(request.getBusinessId())
                .priority(request.getPriority())
                .accessMode("ASYNC")
                .timestamp(System.currentTimeMillis())
                .build();
        
        // 5. 发送到Kafka（根据优先级选择分区）
        try {
            int partition = selectPartitionByPriority(request.getPriority());
            String messageJson = JsonUtil.toJson(message);
            
            kafkaTemplate.send(eventTopic, partition, request.getBusinessId(), messageJson)
                    .get(5, TimeUnit.SECONDS);
            
            log.info("通知已发送到Kafka: notificationId={}, partition={}, priority={}", 
                    notificationId, partition, request.getPriority());
            
            return AsyncPushResponse.builder()
                    .notificationId(notificationId)
                    .eventId(eventId)
                    .status("ACCEPTED")
                    .message("通知已创建，将异步推送")
                    .timestamp(System.currentTimeMillis())
                    .build();
                    
        } catch (Exception e) {
            log.error("发送通知到Kafka失败: notificationId={}, error={}", notificationId, e.getMessage(), e);
            throw new BusinessException(ErrorCode.KAFKA_SEND_FAILED, "通知发送失败");
        }
    }
    
    /**
     * 根据优先级选择分区
     */
    private int selectPartitionByPriority(String priority) {
        if ("HIGH".equals(priority)) {
            // 高优先级：分区 0-3
            return ThreadLocalRandom.current().nextInt(4);
        } else {
            // 普通优先级：分区 4-11
            return ThreadLocalRandom.current().nextInt(8) + 4;
        }
    }
}
```

```java
@Service
@Slf4j
public class EventPublishService {
    
    @Autowired
    private KafkaTemplate<String, String> kafkaTemplate;
    
    @Value("${kafka.topic.notification-events}")
    private String eventTopic;
    
    /**
     * HTTP方式发布事件 - 转发到Kafka
     */
    public EventPublishResponse publishEventViaHttp(EventPublishRequest request) {
        // 1. 生成事件ID
        String eventId = IdGenerator.generateEventId();
        
        // 2. 构建Kafka消息（与直连Kafka的格式完全一致）
        EventMessage message = EventMessage.builder()
                .eventId(eventId)
                .eventType(request.getEventType())
                .eventData(request.getEventData())
                .businessId(request.getBusinessId())
                .source(request.getSource() != null ? request.getSource() : "http-api")
                .timestamp(request.getTimestamp() != null ? 
                        request.getTimestamp() : System.currentTimeMillis())
                .idempotentKey(generateIdempotentKey(request))
                .build();
        
        // 3. 发送到Kafka（同步发送，确保接收成功）
        try {
            String messageJson = JsonUtil.toJson(message);
            SendResult<String, String> result = kafkaTemplate
                    .send(eventTopic, request.getBusinessId(), messageJson)
                    .get(5, TimeUnit.SECONDS);  // 5秒超时
            
            log.info("事件已发送到Kafka: eventId={}, topic={}, partition={}, offset={}", 
                    eventId, eventTopic, 
                    result.getRecordMetadata().partition(),
                    result.getRecordMetadata().offset());
            
            return EventPublishResponse.builder()
                    .eventId(eventId)
                    .status("ACCEPTED")
                    .message("事件已接收，将异步推送")
                    .timestamp(System.currentTimeMillis())
                    .build();
                    
        } catch (Exception e) {
            log.error("发送事件到Kafka失败: eventId={}, error={}", eventId, e.getMessage(), e);
            throw new BusinessException(ErrorCode.KAFKA_SEND_FAILED, "事件发送失败: " + e.getMessage());
        }
    }
    
    /**
     * 批量发布事件
     */
    public BatchPublishResponse publishEventBatch(BatchPublishRequest request) {
        int total = request.getEvents().size();
        int success = 0;
        int failed = 0;
        List<EventPublishResponse> results = new ArrayList<>();
        
        for (EventPublishRequest event : request.getEvents()) {
            try {
                EventPublishResponse response = publishEventViaHttp(event);
                results.add(response);
                success++;
            } catch (Exception e) {
                log.error("批量发布事件失败: eventType={}, error={}", 
                        event.getEventType(), e.getMessage());
                results.add(EventPublishResponse.builder()
                        .eventId(null)
                        .status("FAILED")
                        .message("发送失败: " + e.getMessage())
                        .build());
                failed++;
            }
        }
        
        return BatchPublishResponse.builder()
                .total(total)
                .success(success)
                .failed(failed)
                .results(results)
                .build();
    }
    
    /**
     * 生成幂等性Key
     */
    private String generateIdempotentKey(EventPublishRequest request) {
        if (request.getBusinessId() != null) {
            return request.getBusinessId() + ":" + request.getEventType();
        }
        return null;
    }
}
```

#### 4.3.7 Kafka消费者 (EventKafkaConsumer.java)
```java
@Component
@Slf4j
public class EventKafkaConsumer {
    
    @Autowired
    private EventProcessService eventProcessService;
    
    @Autowired
    private FailedMessageRepository failedMessageRepository;
    
    /**
     * 批量消费Kafka事件
     */
    @KafkaListener(
        topics = "${kafka.topic.notification-events}",
        groupId = "${spring.kafka.consumer.group-id}",
        containerFactory = "kafkaListenerContainerFactory"
    )
    public void consumeEvents(
            List<ConsumerRecord<String, String>> records,
            Acknowledgment acknowledgment) {
        
        log.info("接收到批量事件: count={}", records.size());
        
        List<FailedMessage> failedMessages = new ArrayList<>();
        int successCount = 0;
        
        for (ConsumerRecord<String, String> record : records) {
            try {
                // 解析消息
                EventMessage eventMessage = parseEventMessage(record.value());
                
                // 幂等性检查
                if (isDuplicate(eventMessage)) {
                    log.warn("重复事件，跳过处理: eventId={}", eventMessage.getEventId());
                    successCount++;
                    continue;
                }
                
                // 处理事件
                eventProcessService.processEvent(eventMessage);
                successCount++;
                
            } catch (Exception e) {
                log.error("处理Kafka消息失败: topic={}, partition={}, offset={}, error={}",
                        record.topic(), record.partition(), record.offset(), e.getMessage(), e);
                
                // 记录失败消息
                FailedMessage failedMessage = new FailedMessage();
                failedMessage.setTopic(record.topic());
                failedMessage.setPartition(record.partition());
                failedMessage.setOffset(record.offset());
                failedMessage.setMessageKey(record.key());
                failedMessage.setMessageValue(record.value());
                failedMessage.setErrorMessage(e.getMessage());
                failedMessage.setStackTrace(getStackTrace(e));
                failedMessage.setStatus("PENDING");
                failedMessages.add(failedMessage);
            }
        }
        
        // 批量保存失败消息
        if (!failedMessages.isEmpty()) {
            failedMessageRepository.saveAll(failedMessages);
            log.warn("批量处理完成: total={}, success={}, failed={}", 
                    records.size(), successCount, failedMessages.size());
        } else {
            log.info("批量处理完成: total={}, success={}", records.size(), successCount);
        }
        
        // 手动提交offset（即使有失败，也提交，失败消息已记录到数据库）
        acknowledgment.acknowledge();
    }
    
    /**
     * 解析事件消息
     */
    private EventMessage parseEventMessage(String messageValue) {
        try {
            return JsonUtil.parseObject(messageValue, EventMessage.class);
        } catch (Exception e) {
            log.error("解析事件消息失败: message={}", messageValue, e);
            throw new BusinessException(ErrorCode.INVALID_MESSAGE_FORMAT, "消息格式错误");
        }
    }
    
    /**
     * 幂等性检查
     */
    private boolean isDuplicate(EventMessage eventMessage) {
        String eventId = eventMessage.getEventId();
        String idempotentKey = eventMessage.getIdempotentKey();
        
        // 基于eventId检查
        if (eventId != null && eventProcessService.isEventProcessed(eventId)) {
            return true;
        }
        
        // 基于idempotentKey检查（如果提供）
        if (idempotentKey != null && eventProcessService.isIdempotentKeyProcessed(idempotentKey)) {
            return true;
        }
        
        return false;
    }
    
    /**
     * 获取异常堆栈信息
     */
    private String getStackTrace(Exception e) {
        StringWriter sw = new StringWriter();
        PrintWriter pw = new PrintWriter(sw);
        e.printStackTrace(pw);
        String stackTrace = sw.toString();
        // 截取前2000字符
        return stackTrace.length() > 2000 ? stackTrace.substring(0, 2000) : stackTrace;
    }
}
```

#### 4.3.8 事件处理服务 (EventProcessService.java)
```java
@Service
@Slf4j
public class EventProcessService {
    
    @Autowired
    private EventRepository eventRepository;
    
    @Autowired
    private SubscriptionService subscriptionService;
    
    @Autowired
    private NotificationService notificationService;
    
    @Autowired
    private RedisTemplate<String, String> redisTemplate;
    
    /**
     * 处理Kafka消费的事件
     */
    @Transactional
    public void processEvent(EventMessage eventMessage) {
        // 1. 持久化事件
        Event event = saveEvent(eventMessage);
        
        // 2. 记录幂等性Key
        recordIdempotentKey(eventMessage);
        
        // 3. 查找订阅者
        List<Subscription> subscriptions = subscriptionService
                .findActiveSubscriptionsByEventType(event.getEventType());
        
        if (subscriptions.isEmpty()) {
            log.warn("事件无订阅者: eventType={}, eventId={}", 
                    event.getEventType(), event.getEventId());
            return;
        }
        
        log.info("事件匹配到订阅者: eventType={}, eventId={}, subscriptionCount={}",
                event.getEventType(), event.getEventId(), subscriptions.size());
        
        // 4. 创建通知并异步推送
        for (Subscription subscription : subscriptions) {
            notificationService.createAndPushNotification(event, subscription);
        }
    }
    
    /**
     * 保存事件到数据库
     */
    private Event saveEvent(EventMessage eventMessage) {
        Event event = new Event();
        event.setEventId(eventMessage.getEventId());
        event.setEventType(eventMessage.getEventType());
        event.setEventData(JsonUtil.toJson(eventMessage.getEventData()));
        event.setBusinessId(eventMessage.getBusinessId());
        event.setSource(eventMessage.getSource());
        event.setPublishTime(eventMessage.getTimestamp() != null ? 
                Instant.ofEpochMilli(eventMessage.getTimestamp())
                        .atZone(ZoneId.systemDefault())
                        .toLocalDateTime() : 
                LocalDateTime.now());
        event.setCreatedAt(LocalDateTime.now());
        
        return eventRepository.save(event);
    }
    
    /**
     * 记录幂等性Key到Redis
     */
    private void recordIdempotentKey(EventMessage eventMessage) {
        String eventId = eventMessage.getEventId();
        String idempotentKey = eventMessage.getIdempotentKey();
        
        // eventId作为幂等性Key
        if (eventId != null) {
            String key = "event:processed:" + eventId;
            redisTemplate.opsForValue().set(key, "1", Duration.ofDays(7));
        }
        
        // 额外的幂等性Key（如果提供）
        if (idempotentKey != null) {
            String key = "event:idempotent:" + idempotentKey;
            redisTemplate.opsForValue().set(key, "1", Duration.ofDays(7));
        }
    }
    
    /**
     * 检查事件是否已处理
     */
    public boolean isEventProcessed(String eventId) {
        String key = "event:processed:" + eventId;
        return Boolean.TRUE.equals(redisTemplate.hasKey(key));
    }
    
    /**
     * 检查幂等性Key是否已处理
     */
    public boolean isIdempotentKeyProcessed(String idempotentKey) {
        String key = "event:idempotent:" + idempotentKey;
        return Boolean.TRUE.equals(redisTemplate.hasKey(key));
    }
}
```

```java
@Service
@Slf4j
public class EventPublishService {
    
    @Autowired
    private EventRepository eventRepository;
    
    @Autowired
    private SubscriptionService subscriptionService;
    
    @Autowired
    private EventQueue eventQueue;
    
    /**
     * 发布事件
     */
    @Transactional
    public EventResponse publishEvent(PublishEventRequest request) {
        long startTime = System.currentTimeMillis();
        
        // 1. 参数验证
        validateEvent(request);
        
        // 2. 持久化事件
        Event event = new Event();
        event.setEventType(request.getEventType());
        event.setEventData(JsonUtil.toJson(request.getEventData()));
        event.setBusinessId(request.getBusinessId());
        event.setSource(request.getSource());
        event.setPublishTime(request.getTimestamp() != null ? 
            request.getTimestamp() : LocalDateTime.now());
        
        Event saved = eventRepository.save(event);
        
        // 3. 异步推送通知（将事件ID放入队列）
        eventQueue.push(saved.getEventId());
        
        long duration = System.currentTimeMillis() - startTime;
        log.info("事件发布成功: eventId={}, eventType={}, duration={}ms", 
                saved.getEventId(), saved.getEventType(), duration);
        
        // 4. 返回响应
        EventResponse response = new EventResponse();
        response.setEventId(saved.getEventId());
        response.setStatus("ACCEPTED");
        response.setMessage("事件已接收，将异步推送");
        response.setTimestamp(LocalDateTime.now());
        
        return response;
    }
    
    /**
     * 处理事件（异步）
     */
    public void processEvent(String eventId) {
        try {
            // 1. 查询事件
            Event event = eventRepository.findByEventId(eventId)
                .orElseThrow(() -> new BusinessException(ErrorCode.EVENT_NOT_FOUND));
            
            // 2. 查找订阅者
            List<Subscription> subscriptions = subscriptionService.findSubscriptionsByEventType(
                event.getEventType()
            );
            
            if (subscriptions.isEmpty()) {
                log.info("事件没有订阅者: eventId={}, eventType={}", eventId, event.getEventType());
                return;
            }
            
            log.info("事件匹配到{}个订阅者: eventId={}, eventType={}", 
                    subscriptions.size(), eventId, event.getEventType());
            
            // 3. 为每个订阅者创建通知记录
            for (Subscription subscription : subscriptions) {
                notificationPushService.createNotification(event, subscription);
            }
            
        } catch (Exception e) {
            log.error("处理事件失败: eventId={}", eventId, e);
        }
    }
    
    private void validateEvent(PublishEventRequest request) {
        // 事件类型验证
        if (!EventTypeEnum.isValid(request.getEventType())) {
            throw new BusinessException(ErrorCode.INVALID_EVENT_TYPE);
        }
        
        // 事件数据验证
        if (request.getEventData() == null || request.getEventData().isEmpty()) {
            throw new BusinessException(ErrorCode.EMPTY_EVENT_DATA);
        }
        
        // 数据大小限制（1MB）
        String jsonData = JsonUtil.toJson(request.getEventData());
        if (jsonData.length() > 1024 * 1024) {
            throw new BusinessException(ErrorCode.EVENT_DATA_TOO_LARGE);
        }
    }
}
```

### 4.4 适配器模块（核心-供应商解耦）

#### 4.4.0 设计说明

**问题背景**：
不同订阅者（第三方业务系统）的API格式可能完全不同：
- Body格式差异（JSON结构、字段命名、嵌套层级）
- Header要求差异（认证方式、自定义Header）
- 认证方式差异（API Key、Bearer Token、HMAC签名等）

**典型场景示例**：
```
订单系统发布 ORDER_CREATED 事件

订阅者A (CRM系统):
  - API格式: {"event": {"id": "...", "type": "..."}, "data": {...}}
  - 认证: Bearer Token

订阅者B (物流系统):
  - API格式: {"eventId": "...", "eventType": "...", "payload": {...}}
  - 认证: API Key in Header

订阅者C (财务系统):
  - API格式: 扁平结构 {"event_id": "...", "order_id": "...", ...}
  - 认证: HMAC-SHA256 签名
```

**解决方案**：
采用**适配器模式**实现格式转换和系统解耦，支持：
1. **标准格式适配器**（默认）- 适用于自建系统或遵循标准格式的系统
2. **自定义模板适配器** - 通过模板配置适配任意第三方API格式

**系统定位说明**：
本系统专注于**B2B业务系统集成**，不包含：
- ❌ IM平台集成（钉钉、企微、Slack等）
- ❌ 邮件、短信通知
- ❌ 移动端推送
- ❌ WebSocket实时通信

这些属于"消息推送"范畴，与"系统集成"是不同的业务场景。

```java
/**
 * 自定义模板适配器
 * 支持通过配置自定义Body和Header格式，适配任意第三方API
 */
@Component
@Slf4j
public class CustomTemplateAdapter implements NotificationAdapter {
    
    @Override
    public String getName() {
        return "CUSTOM";
    }
    
    @Override
    public boolean supports(Subscription subscription) {
        return "CUSTOM".equals(subscription.getVendorType());
    }
    
    @Override
    public HttpRequest buildRequest(Event event, Subscription subscription) {
        AdapterConfig config = subscription.getAdapterConfigObject();
        if (config == null) {
            throw new BusinessException(ErrorCode.ADAPTER_CONFIG_MISSING);
        }
        
        // 构建Header
        Map<String, String> headers = buildHeaders(event, subscription, config);
        
        // 构建Body（从模板）
        Object body = buildBodyFromTemplate(event, config);
        
        // 超时时间
        int timeout = config.getTimeout() != null ? config.getTimeout() : 30;
        
        return HttpRequest.builder()
                .url(subscription.getCallbackUrl())
                .method(HttpMethod.POST)
                .headers(headers)
                .body(body)
                .timeout(Duration.ofSeconds(timeout))
                .build();
    }
    
    /**
     * 根据模板构建Body
     */
    private Object buildBodyFromTemplate(Event event, AdapterConfig config) {
        String template = config.getBodyTemplate();
        if (template == null || template.isEmpty()) {
            throw new BusinessException(ErrorCode.BODY_TEMPLATE_MISSING);
        }
        
        // 准备变量
        Map<String, Object> eventDataMap = JsonUtil.parseMap(event.getEventData());
        
        // 变量替换
        String result = template
            .replace("${eventId}", event.getEventId())
            .replace("${eventType}", event.getEventType())
            .replace("${timestamp}", event.getPublishTime().toString())
            .replace("${businessId}", event.getBusinessId() != null ? event.getBusinessId() : "");
        
        // 替换事件数据中的字段（支持 ${data.fieldName}）
        if (eventDataMap != null) {
            for (Map.Entry<String, Object> entry : eventDataMap.entrySet()) {
                String placeholder = "${data." + entry.getKey() + "}";
                String value = entry.getValue() != null ? entry.getValue().toString() : "";
                result = result.replace(placeholder, value);
            }
        }
        
        // 如果需要嵌入完整的eventData对象
        result = result.replace("\"${eventData}\"", JsonUtil.toJson(eventDataMap));
        
        // 解析为JSON对象
        return JsonUtil.parseMap(result);
    }
    
    /**
     * 构建Header
     */
    private Map<String, String> buildHeaders(Event event, Subscription subscription, 
                                             AdapterConfig config) {
        Map<String, String> headers = new HashMap<>();
        headers.put("Content-Type", "application/json");
        
        // 从配置中获取Header映射
        Map<String, String> headerMapping = config.getHeaderMapping();
        if (headerMapping != null) {
            for (Map.Entry<String, String> entry : headerMapping.entrySet()) {
                String value = resolveHeaderValue(entry.getValue(), event, subscription);
                headers.put(entry.getKey(), value);
            }
        }
        
        // 处理认证
        addAuthentication(headers, subscription, config);
        
        return headers;
    }
    
    /**
     * 解析Header值（支持变量替换）
     */
    private String resolveHeaderValue(String template, Event event, Subscription subscription) {
        return template
            .replace("${eventId}", event.getEventId())
            .replace("${eventType}", event.getEventType())
            .replace("${timestamp}", String.valueOf(System.currentTimeMillis()));
    }
    
    /**
     * 添加认证信息
     */
    private void addAuthentication(Map<String, String> headers, Subscription subscription, 
                                   AdapterConfig config) {
        String authType = config.getAuthType();
        Map<String, String> authConfig = config.getAuthConfig();
        
        if (authType == null || "NONE".equals(authType)) {
            return;
        }
        
        if (authConfig == null) {
            log.warn("认证类型为{}，但authConfig为空", authType);
            return;
        }
        
        switch (authType) {
            case "API_KEY":
                String apiKey = authConfig.get("apiKey");
                String headerName = authConfig.getOrDefault("headerName", "X-API-Key");
                headers.put(headerName, apiKey);
                break;
                
            case "BEARER":
                String token = authConfig.get("token");
                headers.put("Authorization", "Bearer " + token);
                break;
                
            case "BASIC":
                String username = authConfig.get("username");
                String password = authConfig.get("password");
                String credentials = Base64.getEncoder()
                    .encodeToString((username + ":" + password).getBytes());
                headers.put("Authorization", "Basic " + credentials);
                break;
                
            default:
                log.warn("未知的认证类型: {}", authType);
        }
    }
}
```

#### 4.4.2 通知推送服务 (NotificationPushService.java)
```java
@Service
@Slf4j
public class NotificationPushService {
    
    @Autowired
    private NotificationRepository notificationRepository;
    
    @Autowired
    private EventRepository eventRepository;
    
    @Autowired
    private WebClient webClient;
    
    @Autowired
    private SignatureUtil signatureUtil;
    
    /**
     * 创建通知记录
     */
    @Transactional
    public void createNotification(Event event, Subscription subscription) {
        Notification notification = new Notification();
        notification.setEventId(event.getEventId());
        notification.setSubscriptionId(subscription.getSubscriptionId());
        notification.setSubscriberName(subscription.getSubscriberName());
        notification.setCallbackUrl(subscription.getCallbackUrl());
        notification.setStatus(NotificationStatus.PENDING);
        
        Notification saved = notificationRepository.save(notification);
        
        // 立即推送
        pushNotification(saved, event, subscription);
    }
    
    /**
     * 推送通知
     */
    public void pushNotification(Notification notification, Event event, Subscription subscription) {
        long startTime = System.currentTimeMillis();
        
        try {
            // 1. 构建通知内容
            Map<String, Object> payload = buildNotificationPayload(event);
            
            // 2. 生成签名
            String signature = null;
            if (subscription.getSecretKey() != null) {
                signature = signatureUtil.sign(JsonUtil.toJson(payload), subscription.getSecretKey());
            }
            
            // 3. 发送HTTP请求
            WebClient.RequestHeadersSpec<?> request = webClient.post()
                .uri(notification.getCallbackUrl())
                .contentType(MediaType.APPLICATION_JSON)
                .header("X-Event-Id", event.getEventId())
                .header("X-Event-Type", event.getEventType())
                .bodyValue(payload);
            
            if (signature != null) {
                request.header("X-Signature", signature);
            }
            
            ClientResponse response = request.exchange()
                .timeout(Duration.ofSeconds(30))
                .block();
            
            int statusCode = response.statusCode().value();
            String responseBody = response.bodyToMono(String.class)
                .defaultIfEmpty("")
                .block();
            
            long duration = System.currentTimeMillis() - startTime;
            
            // 4. 处理响应
            if (statusCode >= 200 && statusCode < 300) {
                handleSuccess(notification, statusCode, responseBody, duration);
            } else {
                handleFailure(notification, statusCode, responseBody, duration, 
                    "HTTP错误: " + statusCode);
            }
            
        } catch (Exception e) {
            long duration = System.currentTimeMillis() - startTime;
            handleFailure(notification, null, null, duration, e.getMessage());
        }
    }
    
    /**
     * 处理推送成功
     */
    private void handleSuccess(Notification notification, int statusCode, 
                               String responseBody, long duration) {
        notification.setStatus(NotificationStatus.SUCCESS);
        notification.setResponseCode(statusCode);
        notification.setResponseBody(truncate(responseBody, 1000));
        notification.setDuration((int) duration);
        
        if (notification.getFirstAttemptTime() == null) {
            notification.setFirstAttemptTime(LocalDateTime.now());
        }
        notification.setLastAttemptTime(LocalDateTime.now());
        
        notificationRepository.save(notification);
        
        log.info("通知推送成功: notificationId={}, statusCode={}, duration={}ms",
                notification.getNotificationId(), statusCode, duration);
    }
    
    /**
     * 处理推送失败
     */
    private void handleFailure(Notification notification, Integer statusCode,
                              String responseBody, long duration, String errorMessage) {
        notification.setRetryCount(notification.getRetryCount() + 1);
        notification.setResponseCode(statusCode);
        notification.setResponseBody(truncate(responseBody, 1000));
        notification.setErrorMessage(truncate(errorMessage, 1000));
        notification.setDuration((int) duration);
        
        if (notification.getFirstAttemptTime() == null) {
            notification.setFirstAttemptTime(LocalDateTime.now());
        }
        notification.setLastAttemptTime(LocalDateTime.now());
        
        // 判断是否还需要重试
        if (notification.getRetryCount() >= notification.getMaxRetryCount()) {
            notification.setStatus(NotificationStatus.FAILED);
            log.error("通知推送最终失败: notificationId={}, retryCount={}, error={}",
                    notification.getNotificationId(), notification.getRetryCount(), errorMessage);
        } else {
            notification.setStatus(NotificationStatus.RETRYING);
            
            // 计算下次重试时间（指数退避）
            LocalDateTime nextRetryTime = calculateNextRetryTime(notification.getRetryCount());
            notification.setNextRetryTime(nextRetryTime);
            
            log.warn("通知推送失败，将重试: notificationId={}, retryCount={}, nextRetryTime={}, error={}",
                    notification.getNotificationId(), notification.getRetryCount(), 
                    nextRetryTime, errorMessage);
        }
        
        notificationRepository.save(notification);
    }
    
    /**
     * 计算下次重试时间（指数退避）
     */
    private LocalDateTime calculateNextRetryTime(int retryCount) {
        // 延迟时间：1min, 5min, 15min, 1hour, 4hour
        long[] delaysInMinutes = {1, 5, 15, 60, 240};
        int index = Math.min(retryCount - 1, delaysInMinutes.length - 1);
        long delayMinutes = delaysInMinutes[index];
        
        return LocalDateTime.now().plusMinutes(delayMinutes);
    }
    
    /**
     * 构建通知负载
     */
    private Map<String, Object> buildNotificationPayload(Event event) {
        Map<String, Object> payload = new HashMap<>();
        payload.put("eventId", event.getEventId());
        payload.put("eventType", event.getEventType());
        payload.put("timestamp", event.getPublishTime());
        payload.put("data", JsonUtil.parseMap(event.getEventData()));
        
        if (event.getBusinessId() != null) {
            payload.put("businessId", event.getBusinessId());
        }
        
        return payload;
    }
    
    private String truncate(String str, int maxLength) {
        if (str == null) {
            return null;
        }
        return str.length() > maxLength ? str.substring(0, maxLength) : str;
    }
}
```

```java
@Component
@Slf4j
public class RetryScheduler {
    
    @Autowired
    private NotificationRepository notificationRepository;
    
    @Autowired
    private NotificationPushService notificationPushService;
    
    @Autowired
    private EventRepository eventRepository;
    
    @Autowired
    private SubscriptionService subscriptionService;
    
    /**
     * 定时扫描需要重试的通知
     * 每分钟执行一次
     */
    @Scheduled(fixedRate = 60000) // 60秒
    public void scanRetryNotifications() {
        try {
            // 查询需要重试的通知
            List<Notification> notifications = notificationRepository.findRetryableNotifications(
                NotificationStatus.RETRYING,
                LocalDateTime.now()
            );
            
            if (notifications.isEmpty()) {
                return;
            }
            
            log.info("扫描到{}条需要重试的通知", notifications.size());
            
            // 并发重试
            notifications.parallelStream().forEach(notification -> {
                try {
                    retryNotification(notification);
                } catch (Exception e) {
                    log.error("重试通知失败: notificationId={}", 
                            notification.getNotificationId(), e);
                }
            });
            
        } catch (Exception e) {
            log.error("扫描重试通知任务失败", e);
        }
    }
    
    /**
     * 重试通知
     */
    private void retryNotification(Notification notification) {
        // 1. 查询事件
        Event event = eventRepository.findByEventId(notification.getEventId())
            .orElse(null);
        if (event == null) {
            log.error("事件不存在: eventId={}", notification.getEventId());
            return;
        }
        
        // 2. 查询订阅
        Subscription subscription = subscriptionService.findBySubscriptionId(
            notification.getSubscriptionId()
        ).orElse(null);
        if (subscription == null) {
            log.error("订阅不存在: subscriptionId={}", notification.getSubscriptionId());
            return;
        }
        
        // 3. 重新推送
        notificationPushService.pushNotification(notification, event, subscription);
    }
    
    /**
     * 定时清理过期通知记录
     * 每天凌晨2点执行
     */
    @Scheduled(cron = "0 0 2 * * ?")
    public void cleanExpiredNotifications() {
        try {
            LocalDateTime expireTime = LocalDateTime.now().minusDays(30);
            
            int count = notificationRepository.deleteByCreatedAtBefore(expireTime);
            
            log.info("清理过期通知记录: count={}", count);
            
        } catch (Exception e) {
            log.error("清理过期通知记录失败", e);
        }
    }
```

#### 4.6.2 通知消费者 (NotificationConsumer.java)
```java
@Component
@Slf4j
public class NotificationConsumer {
    
    @Autowired
    private EventQueue eventQueue;
    
    @Autowired
    private EventPublishService eventPublishService;
    
    private volatile boolean running = false;
    
    @PostConstruct
    public void start() {
        running = true;
        
        // 启动多个消费者线程
        int consumerCount = 5;
        for (int i = 0; i < consumerCount; i++) {
            final int consumerId = i;
            new Thread(() -> {
                log.info("通知消费者启动: consumerId={}", consumerId);
                consume(consumerId);
            }, "NotificationConsumer-" + i).start();
        }
    }
    
    @PreDestroy
    public void stop() {
        running = false;
        log.info("通知消费者停止");
    }
    
    private void consume(int consumerId) {
        while (running) {
            try {
                // 从队列中取出事件ID
                String eventId = eventQueue.pop();
                
                if (eventId != null) {
                    log.debug("消费者{}处理事件: eventId={}", consumerId, eventId);
                    
                    // 处理事件
                    eventPublishService.processEvent(eventId);
                }
                
            } catch (Exception e) {
                log.error("消费者{}处理事件失败", consumerId, e);
                
                // 避免异常导致死循环
                try {
                    Thread.sleep(1000);
                } catch (InterruptedException ie) {
                    Thread.currentThread().interrupt();
                }
            }
        }
    }
}
```

### 5.2 事件接入方式

系统支持两种事件接入方式，业务系统可根据实际情况选择：

#### 5.2.1 方式一：HTTP API接入（推荐快速接入）

**适用场景**：
- 没有Kafka基础设施的轻量级系统
- 快速接入和测试场景
- 事件量较小（< 1000 QPS）
- 希望降低接入复杂度

**接口定义**：
```
POST /api/v1/events
Content-Type: application/json

Request Body:
{
  "eventType": "ORDER_CREATED",
  "eventData": {
    "orderId": "ORD001",
    "userId": "USR123",
    "amount": 299.00
  },
  "businessId": "ORD001",
  "source": "order-service",
  "timestamp": 1725603000000
}

Response:
{
  "code": 200,
  "message": "success",
  "data": {
    "eventId": "evt_789012",
    "status": "ACCEPTED",
    "message": "事件已接收，将异步推送",
    "timestamp": 1725603001234
  }
}
```

**字段说明**：
- `eventType`: 事件类型（必填）
- `eventData`: 事件数据（必填），JSON对象
- `businessId`: 业务ID（可选），用于关联业务对象
- `source`: 来源系统（可选），默认为"http-api"
- `timestamp`: 事件时间戳（可选），毫秒级，默认为当前时间

**批量发布接口**：
```
POST /api/v1/events/batch
Content-Type: application/json

Request Body:
{
  "events": [
    {
      "eventType": "ORDER_CREATED",
      "eventData": {...},
      "businessId": "ORD001"
    },
    {
      "eventType": "ORDER_PAID",
      "eventData": {...},
      "businessId": "ORD001"
    }
  ]
}

Response:
{
  "code": 200,
  "message": "success",
  "data": {
    "total": 2,
    "success": 2,
    "failed": 0,
    "results": [...]
  }
}
```

**限制说明**：
- 单次请求最多100个事件
- 单个事件大小不超过1MB
- 需要API Key认证（Header: X-API-Key）

**HTTP接入示例（Java）**：
```java
@Service
public class EventPublisher {
    
    @Autowired
    private RestTemplate restTemplate;
    
    @Value("${notification.api.url}")
    private String apiUrl;
    
    @Value("${notification.api.key}")
    private String apiKey;
    
    public void publishEvent(String eventType, Map<String, Object> eventData, String businessId) {
        HttpHeaders headers = new HttpHeaders();
        headers.setContentType(MediaType.APPLICATION_JSON);
        headers.set("X-API-Key", apiKey);
        
        Map<String, Object> request = new HashMap<>();
        request.put("eventType", eventType);
        request.put("eventData", eventData);
        request.put("businessId", businessId);
        request.put("source", "order-service");
        
        HttpEntity<Map<String, Object>> entity = new HttpEntity<>(request, headers);
        
        ResponseEntity<Map> response = restTemplate.postForEntity(
            apiUrl + "/api/v1/events", 
            entity, 
            Map.class
        );
        
        log.info("事件发布成功: {}", response.getBody());
    }
}
```

#### 5.2.2 方式二：Kafka直连（推荐高性能场景）

**适用场景**：
- 已有Kafka基础设施的系统
- 高吞吐量场景（> 1000 QPS）
- 追求极致性能和可靠性
- 需要消息持久化和重放能力

**Kafka Topic**: `notification-events`

**消息格式**（与HTTP转发后的格式完全一致）：
```json
{
  "eventId": "evt_789012",
  "eventType": "ORDER_CREATED",
  "eventData": {
    "orderId": "ORD001",
    "userId": "USR123",
    "amount": 299.00
  },
  "businessId": "ORD001",
  "source": "order-service",
  "timestamp": 1725603000000,
  "idempotentKey": "ORD001:ORDER_CREATED"
}
```

**Kafka生产者配置**：
```yaml
spring:
  kafka:
    bootstrap-servers: localhost:9092
    producer:
      acks: all
      retries: 3
      key-serializer: org.apache.kafka.common.serialization.StringSerializer
      value-serializer: org.apache.kafka.common.serialization.StringSerializer
      properties:
        enable.idempotence: true
```

**Kafka接入示例（Java）**：
```java
@Service
public class EventPublisher {
    
    @Autowired
    private KafkaTemplate<String, String> kafkaTemplate;
    
    public void publishEvent(String eventType, Map<String, Object> eventData, String businessId) {
        EventMessage message = new EventMessage();
        message.setEventId(generateEventId());
        message.setEventType(eventType);
        message.setEventData(eventData);
        message.setBusinessId(businessId);
        message.setSource("order-service");
        message.setTimestamp(System.currentTimeMillis());
        message.setIdempotentKey(businessId + ":" + eventType);
        
        String messageJson = JSON.toJSONString(message);
        kafkaTemplate.send("notification-events", businessId, messageJson);
        
        log.info("事件已发送到Kafka: eventType={}, eventId={}", eventType, message.getEventId());
    }
    
    private String generateEventId() {
        return "evt_" + UUID.randomUUID().toString().replace("-", "").substring(0, 16);
    }
}
```

#### 5.2.3 两种方式对比

| 对比项 | HTTP API | Kafka直连 |
|--------|----------|-----------|
| 接入复杂度 | ⭐ 简单 | ⭐⭐⭐ 中等 |
| 性能 | ⭐⭐ 中等 | ⭐⭐⭐⭐⭐ 高 |
| 吞吐量 | < 1000 QPS | > 10000 QPS |
| 可靠性 | ⭐⭐⭐ 良好 | ⭐⭐⭐⭐⭐ 极高 |
| 依赖 | 无 | 需要Kafka客户端 |
| 适用场景 | 小型系统、快速接入 | 大型系统、高性能要求 |
| 推荐程度 | 轻量级系统首选 | 企业级系统首选 |

**选择建议**：
- **初期/测试阶段**：使用HTTP API，快速验证功能
- **生产环境/高并发**：使用Kafka直连，获得最佳性能
- **混合使用**：核心业务用Kafka，辅助业务用HTTP API
